# 故障排查

## 窗口打不开：`Failed to resolve Python.Runtime.Loader.Initialize`

**现象**：`python main.py` 启动后直接退出，堆栈末尾是

```
File "webview\platforms\winforms.py", line 17, in <module>
    import clr
...
RuntimeError: Failed to resolve Python.Runtime.Loader.Initialize from
D:\小说辅助\.venv\Lib\site-packages\pythonnet\runtime\Python.Runtime.dll
```

**原因**：工作区目录（连带 `.venv`）被打上了 **Low 完整性级别**标签。
.NET Framework 出于安全考虑**拒绝从低完整性文件加载程序集**，于是 `pythonnet`
加载失败 → `pywebview` 无法初始化 WinForms → 窗口起不来。

与代码无关：`.venv\Scripts\python.exe -c "import clr"` 在不引入任何项目代码的
情况下就会失败。

**判定**：

```bat
icacls "D:\小说辅助" | findstr /i "Mandatory"
```

输出里出现 `Low Mandatory Level` 即命中本问题。

**修复**（一条命令，继承标签会自动下推到全部子项）：

```bat
icacls "D:\小说辅助" /setintegritylevel (OI)(CI)Medium
```

PowerShell 里必须给 `(OI)(CI)Medium` 加引号，否则会被当成表达式解析。

**验证**：

```bat
.venv\Scripts\python.exe -c "import clr; print('ok')"
```

打印 `ok` 后窗口就能正常打开。

### 同一原因的其它症状

- `black --check` 卡住不返回（低完整性进程写不了 `%LOCALAPPDATA%` 的缓存目录；
  临时绕过用 `--no-cache`）
- `tempfile.gettempdir()` 返回仓库根目录而不是 `%TEMP%`（C 盘临时目录写不进去，
  Python 回退到当前工作目录，于是 `pytest-of-*`、`inkwell-e2e-*` 堆在仓库根，
  `.gitignore` 已忽略）
- 命令行 shell 启动即报 DLL 初始化失败（`0xC0000142`）、`import clr` 报
  `Failed to resolve Python.Runtime.Loader.Initialize`

### 修复后收尾

`icacls` 修好之后，仓库根可能还留着修复前生成的 `pytest-of-Administrator/`（0.5 MB 级）与
`inkwell-e2e-*` 临时目录。确认

```bat
.venv\Scripts\python.exe -c "import clr; print('ok')"
```

打印 `ok` 后，这些残留目录**可以直接删**——它们只在 `.gitignore` 里占位，不会入库。
（2026-10-24 已清理过一次：508 KB）

### 背景

该标签由 DSH 沙盒在**授予工作区写入权限**时附加。在这个目录里开新的 Agent
会话时可能被重新打上——按上面的命令恢复即可，不需要改任何代码或重装依赖。

## 重建索引后「完整自检」报 `malformed inverted index`

**现象**：P9 里先点「重建全文索引」（#42），紧接着点「数据库自检（完整）」（#52），
状态栏提示

```
自检发现问题：malformed inverted index for FTS5 table main.chapter_fts
```

**结论：库没有坏。** 这是 SQLite 3.44+ 的 `PRAGMA integrity_check` 开始一并校验 FTS5
索引后，与 FTS5 的 **per-connection 结构缓存**叠加产生的**一次性误报**。

**判定**（三条都正常即误报，不是数据损坏）：

```bat
:: ① 再点一次「数据库自检（完整）」→ 变成「自检通过（完整…）」（缓存已刷掉）
:: ② 绕开应用连接池，用独立连接直接查库
.venv\Scripts\python.exe -c "import sqlite3;print(sqlite3.connect(r'D:\小说辅助\data\inkwell.db').execute('PRAGMA integrity_check').fetchall())"
:: ③ FTS5 自己的核对命令不报错
.venv\Scripts\python.exe -c "import sqlite3;c=sqlite3.connect(r'D:\小说辅助\data\inkwell.db');c.execute(\"INSERT INTO chapter_fts(chapter_fts) VALUES('integrity-check')\");print('ok')"
```

**原因**：`rebuild` 会换掉整套 FTS5 结构（新的 `%_config` / `%_data` 段）。连接池里
「此前读过或写过该索引」的连接仍缓存着旧结构，它下一次 `PRAGMA integrity_check`
拿旧结构去对新的索引数据，于是报 malformed。**检索结果不受影响**，同一连接再查一次
（缓存被刷掉）或换一条连接就恢复。

**修复**（3.9 前置，2026-10-24 已落地）：

- `backend/database.py`：`integrity_check()` 改为**一次性的独立连接**。完整自检的语义是
  「校验磁盘上的库」，不把连接态历史带进结果（`quick_check` 不校验 FTS5，仍走连接池）。
- `backend/services/maintenance_service.py`：`rebuild_fts()` 提交后调用
  `database.recycle_connections()` 回收连接池，让所有连接重新加载结构。
- 回归用例：`tests/test_settings_maintenance.py`
  （`test_integrity_after_fts_rebuild_not_fooled_by_stale_connection`、
  `test_rebuild_fts_recycles_connection_pool`）。

**复核**：`window_smoke.py` 的 P9「重建索引 → 完整自检」连跑 5 次全过
（修复前 5 次里挂 2~3 次，报的就是上面这条文案）。
