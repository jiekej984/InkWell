## 二、B1：取消按钮的两个坑（不只是 preventDefault）

原实现有两层问题，只改 `preventDefault` 的顺序修不干净：

1. 取消按钮是 `type="submit"`，而表单里「书名」是 `required`——**书名空着时浏览器连 submit 事件都不发**，
   取消点击直接被必填校验吞掉；
2. 就算发出了 submit，回调第一行 `preventDefault()` 已经把 `<dialog method="dialog">` 的原生关闭拦掉，
   随后的 `return` 只是什么都不做。

因此按「取消不做 submit」重构：

- `index.html`：四个对话框（项目 / 通用输入 / 章节信息 / 删卷）的取消按钮统一改成
  `type="button" data-dialog-cancel="cancel"`，`value="cancel"` 不再承担语义；
- `app.js` 新增 `setupDialogs()`：一次事件委托，凡点 `[data-dialog-cancel]` 就 `closest('dialog').close(...)`；
- `projects.js`：submit 回调只处理保存（`event.submitter.id === 'save-project'`），
  并且**先 return 后 preventDefault**（保留原生关闭路径，防止将来又踩同一个坑）；
- 顺带修掉两个衍生问题：① 取消后 `project-cover` 文件输入未清空，下次保存会把上次选的封面偷偷上传——
  现在开对话框即重置；② 保存成为唯一的 submit 按钮，**回车默认行为从「取消」变成「保存」**。

> 覆盖：项目 / 通用输入（新建卷、新建章、重命名）/ 章节信息 / 删卷四类对话框，均走同一套关闭逻辑。

## 三、B2：设定文档删除入口

- 行结构改成 `div.tree__row` = `button.tree__chapter`（打开）+ `button.tree__delete`（✕ 删除），
  沿用 3.3 卡片「展示区与操作区是兄弟节点」的约定（不嵌套交互元素）；
- 删除按钮**常显**（`--text-2`、24×24 命中区），hover / `:focus-visible` 转 `--danger` + `--danger-soft`；
  `title` + `aria-label` 都写明「删除「文档名」」；
- 点击 → `window.confirm` 二次确认（NFR-U3，文案说明「未保存修改会丢弃、30 天内可在回收站恢复」）→
  `DELETE /documents/{did}`（后端 2.7 就有，软删除进回收站）→ 刷新列表；
- **删除当前打开的文档**时：清空编辑器 → 自动打开剩余第一篇 → 状态栏提示「已删除「X」，可在回收站恢复」；
  一篇不剩时回到「还没有文档」空态。

## 四、B3：代码块保存往返（D-3.4-1 关闭）

问题根因有三段，缺一不可：

1. Quill 2 的代码块 DOM 是 `div.ql-code-block-container > div.ql-code-block`；
2. 服务端消毒白名单不含 `div`，保存时容器被剥掉，只剩纯文本；
3. Quill 载入端只认 `<pre>`（clipboard matcher「pre」），所以**把 `div` 加进白名单也救不回来**。

修法取「保存前规范化」：`frontend/js/editor.js` 新增纯函数式 `normalizeCodeBlocks(html)`，
把每个容器改写成 `<pre><code>行1\n行2</code></pre>`；章节保存、章节暂存（`drafts.persist` /
`saveLocalDraft` / 关闭前兜底）与设定文档保存全部改走该函数（`writer.currentHtml()` 统一入口）。
服务端无需改动，重开时 Quill 按 `pre` 重建代码块。

回归（`window_smoke` 新增 4 步）：把首段转成代码块 → 等自动保存 → 断言**存档里 2 个 `<pre>` 且不含
`ql-code-block-container`** → 点树重开第一章 → 断言编辑器里仍有 2 个代码块容器。

## 五、B5：组合输入期间的占位

- `editor.js`：`compositionstart` → 给编辑区加 `is-composing`，`compositionend` → 移除；
- `style.css`：`.ql-editor.ql-blank.is-composing::before { display: none }`
  （伪元素绝对定位，隐藏不引起正文跳动；组合结束后由 Quill 的 `text-change` 决定 `ql-blank` 是否还在）；
- 回归：`window_smoke` 派发 `CompositionEvent` 断言 `::before` 的 `display` 在组合期间为 `none`、
  组合结束后恢复。**真实输入法仍需按 V-02 人工复核一次**（自动化只能证明「事件 → 样式」这一环）。
