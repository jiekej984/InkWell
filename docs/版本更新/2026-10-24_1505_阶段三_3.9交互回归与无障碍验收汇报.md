## 二、回归 21/22 固化，并抓到两个真缺陷

3.2 的拖拽与右键菜单此前只有一次性临时驱动脚本（未入库），回归 21/22 一直是「端到端手工驱动」。
本轮把它们固化进 `window_smoke.py`（112 → **131 步**）：

| 新增步骤组 | 覆盖 |
|---|---|
| 右键菜单（10 步） | 菜单五项文案与顺序 → 重命名（焦点在标题输入框、标题落库）→ 标记定稿（`status=final` + `change_type=milestone`）→ 删除（树里消失 + 回收站可见） |
| 拖拽排序（9 步） | 首个命名卷创建时默认卷**一次性迁入**（C-04）→ 卷内拖拽后顺序 → 新建第三卷不触发迁入确认 → 跨卷拖拽后归属 |

### 缺陷 1：跨卷拖拽一直是坏的（回归 21 的跨卷分支）

- **现象**：把章节拖到另一个卷，状态栏提示「移动失败：POST … 失败：code=1001 章节不属于该卷」，
  章节原地不动；**同卷内排序却正常**。
- **根因**：`POST /volumes/{vid}/chapters/reorder` 的路径 `vid` 是**源卷**，目标卷放 body 的
  `target_volume_id`；`sidebar.js` 的 `moveChapter()` 把 `targetVolumeId` 塞进了路径。
  同卷排序时源卷 == 目标卷，所以碰巧成立 —— 这也是它一直没被发现的原因。
- **修复**：路径改用 `found.volume.id`（`findChapter()` 已经返回所属卷）。
- **验证**：e2e 跨卷拖拽后 `第三卷=[超长章]`、`第二卷=[五万章, 第一章 改名]`，DOM 与 API 双向一致。

### 缺陷 2：树节点 ← 折叠后焦点丢失

- **现象**：键盘用户在某章上按 ← 折叠该卷后，焦点掉到 `body`，再按 → 也不会展开（键盘事件没了落点），
  只能重新 Tab 一路找回来。
- **根因**：折叠用 `display: none` 隐藏 `.volume__chapters`，被聚焦的按钮随之不可见。
- **修复**：折叠时把焦点交给该卷的折叠按钮；顺带给卷折叠按钮补了 ←/→（折叠 / 展开）、
  ↓ 改为「先展开再进首章」（折叠状态下直接聚焦隐藏章节同样无效）。
- **验证**：`a11y_walk` 新增「折叠后焦点不丢失（落在卷折叠按钮上）」检查。

## 三、无障碍自动化：`tests/e2e/a11y_walk.py`

### 3.1 为什么按键要走 CDP

合成 `KeyboardEvent` **不会触发浏览器默认行为**：Tab 移焦点、Enter 点按钮、Esc 关 `<dialog>`
全部依赖默认行为。只有 `Input.dispatchKeyEvent`（WebView2 的 `CallDevToolsProtocolMethodAsync`）
才是真按键。脚本沿用 `capture_ui.py` 的 native 窗口 + UI 线程 `Invoke` 方式，额外处理了
Enter 需要 `keyDown + text` 才会触发默认点击这一点。

### 3.2 20 项检查

| 组 | 检查 | 实测 |
|---|---|---|
| Tab 顺序 | 项目列表前两站是「搜索 / 设置」、可 Tab 到卡片、只停可交互元素 | 6 站：`nav-search → open-settings → open-backup → open-trash → new-project → card__open` |
| Tab 顺序 | 写作页 36 站覆盖侧栏 / 标题 / 工具栏 / 正文 / 状态栏 | 全部命中，工具栏 20 个按钮，无「掉进普通 div」 |
| 焦点可见 | 键盘聚焦描边 ≥2px | 顶栏 / 侧栏 / 树节点均 2px |
| 打开 | Enter 打开作品（卡片 `role=button`） | 通过 |
| 对话框 | 首字段获焦 / Tab 不逃逸 / Esc 关闭 / 焦点归还 | `#prompt-input` → 4 次 Tab 全在框内 → Esc 关闭 → 焦点回 `#add-chapter` |
| 树键盘 | ↓ 移动 / Home 回首个 / ← 折叠 / → 展开 / 折叠后焦点不丢 | 全部通过 |
| 对比度 | 10 组真实渲染配色的 WCAG 比值（正文 4.5 / 大字 3.0） | 4.72 ~ 14.16，无低于阈值项 |
| 缩放 | 100 / 125 / 150% 无横向溢出、关键区域可见、正文行宽 ≤760 | 溢出 0 / 0 / 0px；maxWidth 恒 760px |
| 稳定性 | 页面无 JS 异常 | `[]` |

## 六、待人工确认（验收单 M1~M6）

自动化能覆盖「键盘可达 / 配色 / 页面缩放」，以下几项只能真机人眼：

1. **真实中文输入法**逐键复核（组合期间不误触快捷键、候选窗不遮挡占位、上屏不错位）；
2. **系统显示缩放** 125% / 150%（Windows 显示设置，不是页面缩放）下的真机观感；
3. 截图基线人工对照（`baseline_*` vs `after_3_9_*`）；
4. 关窗前强制保存（`beforeunload`，自动化不能真关窗口）；
5. 800 章大纲树**首次**渲染耗时（AC-1；保存后的重绘已改增量更新）；
6. 真机快捷键与 IME 复核（V-02/V-03 遗留项）。
