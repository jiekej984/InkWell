## 一、结论（先看这张表）

| 验收项 | 目标 | 实测 | 结论 |
|---|---|---|---|
| **AC-2 冷启动**（进程起 → 项目列表可交互） | ≤ 3s | **978 ms**（5 次中位数；975 / 975 / 978 / 982 / 1106） | ✅ 余量 3 倍 |
| **AC-3 打开 5 万字章节到可编辑** | ≤ 1s | **97 ms** | ✅ 余量 10 倍 |
| **AC-10 检索（后端，10 万字项目）** | ≤ 1s | p50 **14.2 ms** / p95 31.5 ms | ✅ 余量 30 倍 |
| **AC-10 检索（UI：输入 → 首条命中）** | ≤ 1s | **55 ms**（20 条命中） | ✅ |
| **AC-1 大纲树（2001 章全量渲染）** | 「不卡」 | **492 ms** | ✅ 远低于 M5 的 800 章 ≤1s |
| **§12.1 导出 500 万字** | ≤ 60s（假设） | **310.8 ms**（5,050,000 字 / 15.2 MB / 2001 章） | ✅ 假设保守了 190 倍 |

**一句话**：五个性能验收项全部达标，且余量很大；唯一需要决策的是「常驻内存」的**测量口径**与重负载下的超出。

## 二、测量环境与方法

### 2.1 环境（实际机器，非假定中位机）

| 项 | 值 |
|---|---|
| CPU | AMD Ryzen 7 8845H（8 核 16 线程） |
| 内存 | 15.3 GB |
| 磁盘 | SSD（477 GB + 954 GB） |
| 系统 | Windows 10.0.22631 |
| 产物 | PyInstaller onedir，`dist/Inkwell/`，54.2 MB |

> 报告 D-06 的「中位机 i5-10代 / 8G / SSD」是**更低**的规格；本机更快，所以这些数字对目标机器是**乐观值**，
> 但普遍有数量级余量（最短的一项 AC-2 也有 3 倍），不构成风险。

### 2.2 口径

| 项 | 起 | 止 |
|---|---|---|
| AC-2 | `CreateProcess` 返回（进程起） | 项目列表卡片可见（前端自己拉到 `/api/projects` 并渲染） |
| AC-3 | 点击「五万字章」节点 | 章节标题就绪 + 正文 >4 万字 + 编辑器可编辑 |
| AC-1 | 点击项目卡 | `.tree__chapter` 节点数稳定 = 2001 |
| AC-10（后端） | 请求发出 | 响应返回（10 次，章节关键词 / 设定关键词各 5 次） |
| AC-10（UI） | 点「搜索」 | 首条 `.search-hit` 出现 |
| 内存 | 空闲：首屏后等 2s；重负载：2000 章树 + 5 万字章 + 检索结果都就绪后 | `PrivatePageCount` 求和（**私有**）/ `WorkingSetSize` 求和（**工作集上界**） |

**打点方式**：`backend/perf_probe.py` 只在 `INKWELL_PERF_TRACE=1` 时被 `main.py` 惰性导入，
在窗口内侧调用 `evaluate_js` 打 `[perf]` 日志；**生产启动不加载这个模块**（零开销）。
测量对象是**冻结产物本身**（不是源码模式），因此包含 PyInstaller 引导、WebView2 初始化与真实磁盘 I/O。

### 2.3 数据规模（比验收要求高一档）

- 20 卷 × 100 章 = **2000 章**，每章 2500 字；外加一篇 **5 万字章** → **5,050,000 字（505 万字）**
- 10 份设定文档（含「性能关键词」「守塔人档案」两个检索词）
- 库文件 52.8 MB；导出文件 15.2 MB

> AC-10 要求的是「10 万字项目检索 ≤1s」，本实测用的是 **505 万字**库（50 倍），属于更严格场景。

## 三、逐项结果

### 3.1 AC-2 冷启动：978 ms

| 第几次 | 1 | 2 | 3 | 4 | 5 | 中位数 |
|---|---|---|---|---|---|---|
| 首屏就绪 | 1106 ms | 978 ms | 975 ms | 975 ms | 982 ms | **978 ms** |

第 1 次偏高的 1106 ms 是 WebView2 冷缓存 / 杀软首次扫描，稳定态在 975~982 ms。
**注意**：这是 505 万字库上的冷启动（项目卡要算字数统计），比空库更严苛。

### 3.2 AC-3 打开 5 万字章节：97 ms

点击 → 标题就绪 + 正文 5 万字全部进入 Quill + 可编辑，**97 ms**；AC-3 预算 1000 ms，
余量约 10 倍。第四章 3.4 做的「首行缩进 / 行宽 760px」在 5 万字下没有引入额外布局成本。

### 3.3 AC-1 2001 章大纲树：492 ms

| 规模 | 实测 | 参考 |
|---|---|---|
| 2001 章全量渲染（20 卷） | **492 ms** | 3.9 人工项 M5「800 章首屏 ≤1s」 |
| 800 章 | 未单独测（线性外推 ~200 ms） | — |

结论：**R-UI1（800 章全量重绘卡顿）不成立**，V1.0 不需要虚拟滚动。虚拟滚动仍是 V1.1 的可选项
（2000 章以上或低端机上再做）。

### 3.4 AC-10 检索

| 口径 | p50 | p95 | max | 覆盖 |
|---|---|---|---|---|
| 后端 `/api/search`（10 次） | **14.2 ms** | 31.5 ms | 31.5 ms | 章节命中 ✅ + 设定文档命中 ✅ |
| UI（输入 → 首条命中） | **55 ms** | — | — | 20 条结果 |

FTS5 trigram 索引 + 触发器即时同步（E-01）在 505 万字上仍是「毫秒级」，
离 NFR-P5 的 1s / 3s 有两个数量级余量。

### 3.5 §12.1 导出 500 万字：310.8 ms

```
state=success  elapsed=310.8 ms  chapters=2001  word_count=5,050,000  size=15,192,275 B
```

原假设「≤60s」过于保守（实测快 190 倍）。导出是后台长任务（`POST /projects/{pid}/export`），
不阻塞 UI；310 ms 意味着用户点完基本立刻拿到文件。

### 3.6 内存

| 状态 | 私有内存（NFR-P6 判定口径） | 工作集（上界，共享页重复计入） | 明细 |
|---|---|---|---|
| **空闲**（项目列表，无打开项目） | **284.0 MB** | 453.4 MB | 主进程 147.7 + WebView2 305.6（工作集） |
| **重负载**（2000 章树 + 5 万字章 + 20 条检索结果） | **384.2 MB** | 535.8 MB | 主进程 154.7 + WebView2 381.0（工作集） |

- WebView2 的 6 个进程（浏览器 + 渲染 + GPU + 网络/存储等）是内存主体；
  主进程（Python + FastAPI + SQLite）≈150 MB（工作集）/ 115 MB（私有）。
- 「工作集求和」会把各进程共享的 DLL 页重复计入，所以数值偏高；**私有内存**才是
  「这个应用真正独占多少」的公平口径，也是这里判定 NFR-P6 的依据。

## 四、与报告假设的偏差与待决事项

### 4.1 NFR-P6「常驻内存 ≤300MB」：口径需要定死（**需要你拍板**）

- **空闲态私有内存 284.0 MB ≤ 300 MB → 达标**；
- **重负载态 384.2 MB > 300 MB → 超标**（多出约 100 MB，来自 5 万字章节正文 + 2001 节点树 + 检索结果同时驻留）。

报告 NFR-P6 只写了「常驻内存 ≤300MB」，没写**在什么状态下测**。两个可选结论：

| 方案 | 含义 | 影响 |
|---|---|---|
| **A（推荐）** | 明确「常驻内存」= **空闲/基线态**（打开应用、项目列表），实测 284 MB 达标；重负载作为**参考值**登记 | 不动代码，报告 §2.4 / §12.1 补测量口径 |
| B | 要求**任何状态**都 ≤300MB | 需要做 WebView2 挂起 / 树虚拟滚动 / 检索结果分页优化，属于 V1.1 工作量，且收益有限 |

我倾向 A：写作应用的常态是「打开一个项目写一章」，2000 章树 + 5 万字章 + 检索结果**同时**驻留是极端叠加。

### 4.2 §12.1 假设回填值（4.5 并入报告时用这一组）

| 假设项 | 原值 | 实测 | 处理 |
|---|---|---|---|
| 打包体积 | 35~60 MB | 54.2 MB（zip ~31 MB） | 保持区间，补实测 |
| 冷启动 | 2~3 s | **0.98 s** | 改为「≤1s（实测中位数）」 |
| 常驻内存 | 180~300 MB | 空闲私有 **284 MB** / 重负载私有 384 MB | 补测量口径（见 4.1） |
| 导出 500 万字 | ≤60 s | **0.31 s** | 改为「≤5s（实测 0.31s）」 |
| 检索 10 万字 | ≤1 s（NFR-P5） | 505 万字 p50 **14 ms** | 保持 NFR，补实测 |
| 打开 5 万字章节 | ≤1 s（NFR-P2） | **97 ms** | 保持 NFR，补实测 |

### 4.3 遗留风险（不阻塞）

- 本机是无风扇高性能轻薄本（8845H），**低端机 / 机械硬盘**上冷启动会变慢；建议在发布说明里给出
  「低于 3s 的余量来自 SSD + 现代 CPU」的说明，并在阶段四收口时保留一组低端机数据（如有条件）。
- 内存重负载超标已登记为 **V1.1 可选项**（树虚拟滚动 / WebView2 挂起），不作为阶段四阻塞。

## 五、复现

```bat
:: 1. 先出产物（阶段四构建闸门：构建 + 冻结自检 + 开窗 + WebView2 引导）
.venv\Scripts\python.exe tools\build_release.py

:: 2. 一条命令跑完 AC-1/2/3/10 + 导出 + 内存，结果写 JSON
.venv\Scripts\python.exe tools\perf_probe.py --json docs\版本更新\阶段四_性能实测.json

:: 3. 只要某一项时可跳过导出（更快）
.venv\Scripts\python.exe tools\perf_probe.py --skip-export
```

> 每次都会用临时数据目录造 505 万字（约 21 秒）并自动清理，不读写仓库的 `data/`。
