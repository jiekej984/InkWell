## 四、给 5.2（服务层）的注意点

1. **`ACTIVE_MODELS` 现在含子表**：`active(CharacterAlias)` / `active(OrgMember)` 可直接用，不必手写 `is_deleted == 0`。
2. **`graph_layout` 已建模**：`GraphLayout` 可直接读写，不需要原生 SQL；单行覆盖写 + `updated_at` 做并发校验。
3. **`character_alias` / `org_member` 没有 `deleted_at`**：它们随主体级联，不进回收站；`_purge_scope` 那类按 `deleted_at` 清理的逻辑**不要套到这两张表上**。
4. **唯一性靠部分索引**：服务层捕获 `IntegrityError` 时，要能区分「活跃行冲突」与「其他约束」，并转成 `1001` + 可读消息（如「别名『小昭』已被占用」）。
5. **迁移只能升到最高版本**：将来加 0004 时，`test_migrate` 里构造旧 schema 的辅助函数要同步升级。
