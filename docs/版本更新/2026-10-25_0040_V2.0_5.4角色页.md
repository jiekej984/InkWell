## 二、实现过程中的自查发现（7 项）

| # | 发现 | 处置 |
|---|---|---|
| **F1** | 空态截图里头部仍显示空的角色/状态下拉与「删除」按钮，像坏掉了 | `setHeaderEnabled(false)`：下拉与删除直接 `hidden`，姓名框变占位「还没有角色」并禁用 |
| **F2** | 侧栏标题过长（「空项目（角色库空态）·…」）把「＋角色」挤成两行 | 标题 `min-width:0` + 省略号，按钮 `flex:0 0 auto` |
| **F3** | 立绘首帧把 `?sig=` 空签名塞进 `src`，会闪一下破图 | 先显示姓名首字，拿到 `/api/files/sign` 的签名 URL 再替换并隐藏首字 |
| **F4** | `patchCharacter` 原先用「新值」和「新返回详情」比较来决定是否刷新列表，判断永远为假 | 改为按字段名判断（`name`/`role` 变更才重拉列表） |
| **F5** | 截图脚本第一次跑没关窗口：驱动出错后进程挂住，且 `Select-Object` 缓冲导致看不到日志 | `finally` 里 `window.destroy()`；出错立即 `print`；等待条件改成「目标卡片真实存在」 |
| **F6** | 报告写「失焦保存（debounce 800ms）」，但 `blur` 本身就是离散事件 | **不额外 debounce**：避免切角色时把最后一次输入丢掉；搜索框仍保留 250ms 去抖。若要合并连续字段改动，可后续加 |
| **F7** | 「关系图」入口与「组织 / 阵营」Tab 本任务还没有内容 | 关系图按钮禁用并注明「下一步开放」；两个 Tab 进占位页，5.5 / 5.8 接管 |
