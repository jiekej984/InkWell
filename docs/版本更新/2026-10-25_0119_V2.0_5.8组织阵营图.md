## 二、实现过程中的自查发现（10 项）

| # | 发现 | 处置 |
|---|---|---|
| **Q1** | 重构渲染后 `dom.nodeEls` 没写入，**所有节点都没有 `transform`**，全堆在原点——组织/阵营模式只剩几根线 | 渲染时同步写 Map；截图复核 |
| **Q2** | **阵营 id 与组织 id 撞号**（两张表自增都从 1 开始），阵营 1 与组织 1 无法区分，membership 边指错 | 服务层给阵营节点加 `FACTION_GRAPH_OFFSET = 1_000_000`，边同步偏移；前端把组织身上的原始 `faction_id` 映射到偏移后的节点 id 再聚类；补测试 |
| **Q3** | **边 id 跨表撞号**（阵营关系 id=1 与组织关系 id=1），DOM 映射互相覆盖，一条边永远画不出来 | 边的 DOM 键改成 `类型:id` |
| **Q4** | 阵营簇被排成一条竖线（角度从正上方开始，两个阵营上下相对） | 角度从 0 开始（左右排），组织绕到阵营下方 |
| **Q5** | 组织节点没有人数，只能显示名称 | 服务层补 `member_count`（组织/阵营两种模式都补），补测试 |
| **Q6** | 组织节点 `kind_label` 透传的是英文枚举（`sect`） | 前端用 meta 的 `organization_kinds` 映射中文 |
| **Q7** | 任务要求「保留各自缩放状态」 | `state.views` 按模式存，切换时保存/恢复，首次进入才 `fit` |
| **Q8** | 快速连续切模式时，旧请求可能覆盖新模式的渲染 | `loadToken` 守卫，过期响应直接丢弃 |
| **Q9** | 任务写「卧底成员虚线」，但组织模式只返回组织节点与组织关系，没有成员边 | 记录取舍：卧底身份在角色卡 / 组织成员表体现，图里暂不画成员边（要画需给 5.2 的图接口加成员边，成本高于收益） |
| **Q10** | 组织/阵营节点上「以此为中心」「打开角色卡」不适用 | 右键菜单按模式隐藏这两项，只保留「隐藏节点」 |

## 五、补充：关系名标在线上（用户反馈）

> 反馈：「只用线的颜色表示关系，对色弱的人比较困难，能不能在线中间加上关系名？」

这是对的：纯颜色编码不满足 WCAG 1.4.1（不能只靠颜色传达信息）。已加：

- 每条**语义关系**线的中点标注关系名（师徒 / 血仇 / 结盟 / 敌对 / 战争 / 附庸…），文字带底色描边，压在线上也读得清
- 人物模式优先显示自定义标签；隐秘关系追加「· 秘」
- 同一对节点之间有多条线时，文字沿垂直方向错开，避免叠字
- 顶栏新增「关系文字」开关，默认开，状态存 `localStorage`；截图脚本验证开/关都生效
- **结构线不加字**：组织从属、阵营归属靠形状/箭头与图例区分，避免大树里文字过密
- 颜色仍是辅助编码，不再承担唯一语义
