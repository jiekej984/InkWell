# V2.1 范围与优先级建议

> 状态：2026-10-25 经项目发起人确认并完成实施验收。结果见 `V2.1_验收单.md`。依据 `Inkwell项目报告_v2.2.md`、`V2.0_验收单.md` 与自检阶段二残余项整理。

## 目标

补齐 V2.0 延后但直接影响角色/组织数据可信度与日常检索的事项；先验证组织树容量，再决定是否扩大图谱数据契约。保持 V2.1 作为可控的小版本，不默认把全部延后项都实现。

## 建议范围

| 优先级 | 项目 | 建议决策 | 完成标准 / 验收条件 |
|---|---|---|---|
| P0 | 组织树 50 节点性能基线 | 纳入；布局压测通过，真实窗口拖拽人工验收通过 | 3 层、50 节点下布局 ≤300ms（沿用 AC-19）；保留布局耗时记录；真实窗口拖拽主观感受流畅、无明显卡顿。未采集逐帧 FPS 数值。展开/折叠与摆位仍可用。 |
| P1 | 组织恢复成员批次数据完整性 | 纳入修复；新增迁移 0004，为 `org_member` 增加删除批次时间 | 迁移为旧数据回填 `updated_at`；恢复组织只恢复本次删除的成员，不带回更早手动移除成员；验证迁移前后兼容、主组织唯一性和重复恢复。 |
| P1 | 出场检索 FR-8.23 | 纳入 | 以角色为检索对象，按章节聚合出现位置；明确正文匹配口径、章节软删处理、分页/排序与空结果；结果可跳转到对应章节。 |
| P1 | 关系图边标签避让 | 纳入 | 多条交叉/重叠边仍可辨认关系名；人物图、组织图、阵营图分别覆盖密集与长标签场景；布局变化后标签位置稳定。 |
| P2 | 全图导出 | 作为可选项评估，先保留现有视口导出 | 只有在用户需分享视口外节点时才实现；导出范围需包含全部可见图节点与连线，并有尺寸上限/缩放策略，避免生成不可用的大图。 |
| 暂缓 | 卧底成员虚线 | 暂缓，等待明确用户场景 | 当前图接口是组织节点/组织关系，没有成员边。实现前需定义成员边数据契约、隐蔽成员是否在默认图中暴露、筛选与图例语义；不可仅为满足一条延后记录而默认暴露秘密成员。 |
| 暂缓 | 关系列表隐藏软删对象名称 | 保持现状，待产品口径确认 | 当前关系列表保留被软删对象名称有助于恢复关系上下文，图数据已隐藏软删对象；若未来改为隐藏，需同时设计恢复提示和孤儿关系处理。 |
| 暂缓 | 图布局并发冲突提示刷新 | 延后至多窗口或并发编辑需求出现 | 当前单实例降低冲突概率；届时用高精度版本令牌并在 3002 后刷新本地 stamp，覆盖冲突、重试与丢弃。 |
| 暂缓 | 组织/阵营视图章节过滤 | 先不纳入 | 当前章节过滤契约只为人物模式定义；若需要组织/阵营随章节变化，先明确成员/关系的时间语义和 `include_expired` 的含义。 |

## 建议实施顺序

1. 固化 50 节点性能基线和拖拽采样方法，确认已有 O(n) 布局实际满足 AC-19。
2. 做 `org_member.deleted_at` 迁移及恢复批次修复，优先保护数据完整性。
3. 实现出场检索，先定好聚合、软删、跳转与排序契约。
4. 改进边标签避让并用三种图模式做视觉回归。
5. 根据全图导出的真实使用场景决定是否排入本版本；卧底虚线继续等待安全和需求语义确认。

## 版本边界与待确认项

- V2.1 已进入实现；当前分支为 `codex/v2.1`，schema 目标版本为 4。
- 组织树布局压测与真实窗口拖拽人工验收已通过；无需为此制造额外优化。拖拽 FPS 未做定量采样，不宣称达到数值帧率目标。
- V2.1 实现与验收完成；发布版本号、安装包构建和 GitHub Release 尚待处理，详见 `V2.1_验收单.md`。
- 2.0.1 的 `main` 与 `v2.0.1` 已按授权推送到指定 GitHub 远端；GitHub Release 页面及 ZIP/SHA256 附件尚未创建。
