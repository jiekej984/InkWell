## 二、第 1 条异常复核（2026-10-24 01:05）

**结论：不是产品缺陷，是探针时序问题** —— 首次组合在「章节尚未加载、编辑器未获得焦点」时发出，
WebView2 丢弃了该组合；章节就绪后，空编辑器与非空编辑器的 preedit 均正常。

对照实验（同一空章节，三个时机分别发组合）：

| 时机 | `activeElement` 是编辑器 | 章节标题 | preedit 是否进入 DOM |
|---|---|---|---|
| `.ql-editor` DOM 刚出现（复现原探针时机） | ❌ false | 空 | ❌ 无（`<p><br></p>`） |
| 章节加载完成、编辑器可编辑（未激活窗口） | ✅ true | 空章节 | ✅ `zhong` |
| 激活窗口 + 鼠标点击编辑器后 | ✅ true | 空章节 | ✅ `shuru` |

复测（另一轮、空编辑器 + 激活点击）：首次组合 `nihao` → DOM `<p>nihao</p>`；
同一空编辑器第二次 `zhong`、非空编辑器 `shuru`、重新打开空章节 `kongbai` 均正常显示。

**对 3.3 的约束**：首启引导「新建项目 → 自动建第一章 → 聚焦正文」必须
**在章节加载完成、编辑器 `contenteditable=true` 之后**再 focus/点击，不能在 `.ql-editor` 出现时就聚焦。

## 三、结论与设计约束

1. **V-03 已证实**：WebView2 在 IME 组合期间抛出的 keydown 事件带 `isComposing: true`，
   因此快捷键必须在此时**直接放行，不 preventDefault**；3.7 的快捷键注册表与 3.8 查找条输入统一按此处理。
2. **已修一处真实缺陷**：`writer.js` 的 Ctrl+S（保存 + 手动快照）原先在组合期间也会触发，
   会产生非用户预期的版本；现已加门禁（`DECISIONS.md` S3-03）。
3. **V-02 仍为「部分验证」**：CDP 合成组合与微软拼音的真实行为存在差异
   （preedit 渲染时机、候选窗、标点/emoji、光标位置），不能替代人工 IME 走查；
   但已排除「空编辑器首次输入不可用」这一具体风险点。
4. 粘贴链路：纯文本粘贴正常；富文本（Word/网页）依赖服务端消毒（已有测试覆盖），
   前端视觉表现待人工确认。
