## 七、验收后追加修复：Ctrl+Shift+F 在中文输入法下无反应（S3-17，2026-10-24）

### 7.1 现象

设定文档页正文内按 `Ctrl+Shift+F`，全局搜索**不弹、界面完全无反应**；顶栏「搜索」按钮正常。
写作页 `Ctrl+F` / `Ctrl+S` / `Esc` 正常（`Ctrl+Shift+F` 用户未验证）。

### 7.2 根因（与最初三条猜测都不同）

| 猜测 | 结论 |
|---|---|
| A. `openSearch()` 抛异常被 `.catch` 吞掉 | **否**。后端日志既无 `GET /api/projects`（`openSearch()` → `loadProjectOptions()` 必发），也无 `POST /api/system/logs`（异常上报）→ 快捷键根本没触发 |
| B. `getView()` 在设定页返回异常值 | **否**。`scope=GLOBAL` 本就不看 `view`；且真实按键在项目列表 / 写作页 / 设定页三处表现一致 |
| C. `isComposing` 偶发为 true | **方向对、机制错**。不是偶发，是**微软拼音中文态把 `Ctrl+Shift+F` 当自带的「简体/繁体切换」系统热键**，按键在输入法层就被处理 |

真实 WebView2 + 真实按键（焦点在 Quill 正文）实测：

| 输入法状态 | 页面收到的 keydown | 结果 |
|---|---|---|
| 英文态 | `Control` / `Shift` / **`F`** | 正常打开全局搜索（三个视图均正常） |
| 中文态（未组合） | `Control` / `Shift`（**`F` 缺失**），`F` 的 **keyup 正常到达** | 修复前无反应；修复后由 keyup 兜底打开 |
| 中文态（候选窗未提交） | 全是 `key='Process'` / `keyCode=229` / `isComposing=true` | 交给输入法（S3-12 的 IME 门禁约定），有意不触发 |

**关键点：与视图无关。** 同一时刻在项目列表页按反而正常——那里没有可编辑焦点，输入法不接管；
写作页与设定页同样失败。用户最初观察到「设定文档页坏、写作页正常」是因为**写作页当时只验证了
`Ctrl+F` / `Ctrl+S` / `Esc`**（这三个键输入法不抢）。

### 7.3 修复

1. `frontend/js/hotkeys.js`：新增 **keyup 兜底**——捕获阶段同时监听 `keyup`，只对带
   `Ctrl/Alt/Win` 的**命令组合**再匹配一次（`matchShortcutOnKeyUp()`；`matchShortcut()` 增加
   `ignoreIme` 选项仅供该路径）。keydown 已执行过的组合记入去重表，同一次按键的 keyup 直接跳过
   （**一次按键只触发一次**），修饰键松手时清表；无修饰键的按键（字母 / Esc / Enter）不参与兜底。
2. `frontend/js/app.js`：`openSearch()` 收口到 `runGlobalSearch()`，异常**同时**进 console、
   远端日志与搜索页状态栏（`#search-status`），不再只剩一行 `.catch(log.error)`。
3. 回归入口：`tests/js/hotkeys.test.js`（+8 条）、`window_smoke.py`
   （设定页正文内只派发 keyup，断言打开全局搜索，131 → **132 步**）。

### 7.4 复核证据

| 场景（真实键位） | 修复前 | 修复后 |
|---|---|---|
| 中文态 · 设定页正文 | 无反应（页面只收到 Control/Shift） | **打开全局搜索**（keyup 兜底） |
| 中文态 · 写作页正文 | 无反应（同上） | **打开全局搜索** |
| 中文态 · 项目列表 | 正常 | 正常（keydown 主路径） |
| 英文态 · 三视图 | 正常 | 正常，且 `#search-input` focus 计数每次 **+1**（无二次触发） |

- `pytest` **258 passed**、`node --test` **79 passed**、`window_smoke` **132 步全过**、
  `ruff` / `black --check` / `node --check` 全绿；
- 判定命令与用户侧彻底解法（改微软拼音「简体/繁体切换」热键）见 `docs/故障排查.md`。

### 7.5 残余限制（不阻塞验收）

组合候选窗未提交时按 `Ctrl+Shift+F` 仍由输入法处理——这是 S3-12 有意保留的 IME 门禁（快捷键不抢
输入法的键），不属于本缺陷；用户若在微软拼音设置里改掉该热键，keydown 主路径也会一起恢复。
