## 一、项目背景与目标

### 1.1 背景与痛点

写长篇小说的人，今天大致有五类工具可选，但每一类都在长篇场景下有明显缺陷：

| 现有方案 | 典型问题 |
|---|---|
| Word / WPS / 记事本 | 没有卷章结构；没有全书字数与进度；单文件过大后卡顿；没有版本历史，只有"另存为 xxx_最终版_真的最终版.docx" |
| 网文平台后台（作家助手等） | 必须联网；数据存在平台服务器，作者不掌控；与平台强绑定，换平台即换工具；无法离线写作 |
| Notion / Obsidian 等通用笔记 | 没有"卷-章-字数-版本"的小说领域模型，一切靠模板和插件自己搭；配置成本高于写作收益；字数统计不便 |
| Scrivener 等专业写作软件 | 功能强大但收费、中文语境与汉化支持弱、学习曲线陡峭、不含中文网文工作流 |
| 零散记录（备忘录、微信、群聊） | 灵感、设定、人物小传散落各处，写作时找不到，事后要凭记忆重建 |

**一句话痛点**：长篇作者需要的不是"又一个编辑器"，而是一个**懂小说结构的、数据归自己、不会丢稿、开箱即用的本地工作台**。

### 1.2 目标用户与画像

| 画像 | 特征 | 核心诉求 | V1 服务优先级 |
|---|---|---|---|
| **A. 长篇网文作者** | 20~35 岁，日更 3000~10000 字，常同时开 1~3 本，长期连载 | 写得快、不卡、不丢稿、字数准 | **最高** |
| **B. 传统/严肃文学与出版向作者** | 重结构与设定一致性，周期长，常有世界观/时间线/人物表 | 设定文档与正文并列管理、长周期可靠 | **高** |
| **C. 同人/轻小说/爱好者作者** | 重灵感收集与素材（立绘、场景图） | 灵感库、图库 | 低（V2 覆盖） |

**V1.0 明确优先服务 A 与 B 的交集**：即"在长篇、离线、数据自主要求下，需要卷章结构与设定文档的中文作者"。C 的需求推迟到 V2。

### 1.3 核心价值主张（差异化）

Inkwell 只在这四点做到位，其余功能一律不为 V1 让路：

1. **数据主权**：全量数据落在用户自己的 `Documents/Inkwell/`，纯文本/SQLite 可读可拷，卸载不丢、换机即拷。
2. **零配置体验**：一个 exe，双击即用，不需要装 Python、不需要开浏览器、不需要注册账号、不需要联网。
3. **中文长篇领域模型**：卷-章两级结构 + 字数进度 + 设定文档并列 + 章节版本历史，这些是通用笔记工具给不了的。
4. **可扩展与开源**：模块像插件一样加，代码结构清晰，可持续迭代与社区共建。

### 1.4 项目目标与成功标准

**产品目标**：让一位作者能够**从零开始、完整写完一本 30 万字以上的长篇小说**，全程不丢稿、不卡顿、数据可备份可导出。

**V1.0 发布验收标准（可度量，全部满足方可视为发布）**：

| 编号 | 验收标准 | 判定方式 |
|---|---|---|
| AC-1 | 支撑单项目 ≥20 卷、≥2000 章、单章 ≤5 万字、全书 ≤500 万字 | 用脚本生成压力数据，实测指标满足 §2.4 性能要求 |
| AC-2 | 冷启动（双击 exe 到窗口可交互）≤ 3s | 中位机（i5 + 8G + SSD）实测 5 次取中位数 |
| AC-3 | 打开 5 万字章节到可编辑 ≤ 1s | 同上 |
| AC-4 | 模拟断电/强杀进程后，最多丢失最近 30 秒内输入 | 写作中途 `taskkill /F` 后重启验证 |
| AC-5 | 连续写作 1 小时后，仍可回溯到 60 分钟前的任一内容节点 | 版本历史抽查（对应 §5.3 快照策略） |
| AC-6 | 可一键导出全书为 TXT 与 Markdown，内容与正文一致 | 导出后字数与状态栏总字数误差 ≤0.5% |
| AC-7 | 5 名内测作者完成"导入旧稿 → 写作 → 版本回溯 → 导出"全流程，其中 ≥4 人表示愿意继续使用 | 内测问卷 |
| AC-8 | 开源仓库中，第三方开发者按 README 可在 30 分钟内跑通开发环境 | 找 1 名未参与开发者计时验证 |
| AC-9 | **备份与恢复**：手动损坏数据库后，能从最近一份备份完整恢复（正文、设定文档、版本历史均完整） | 破坏性演练（回归清单第 6 项） |
| AC-10 | **全文搜索**：10 万字项目中检索关键词，响应 ≤1s，且结果同时覆盖章节正文与设定文档 | 构造含 10 组关键词的测试项目 |
| AC-11 | **回收站恢复**：删除章节后 30 天内可完整恢复，含"父卷也已删除"的孤儿场景 | 回归清单第 4 项 + 孤儿场景专项 |

### 1.5 范围界定

**V1.0 范围内（In Scope）**

- 项目基础信息管理（CRUD + 封面 + 标签）
- 卷-章两级大纲与章节写作（富文本）
- 设定文档（世界观/时间线/势力/名词表）
- 自动保存、章节版本历史与回滚
- 字数统计（章节级 + 全书级）
- 全文搜索（章节 + 设定文档）
- 本地备份与恢复、导出 TXT/Markdown
- 回收站（误删恢复）
- Windows 10/11 x64 打包分发

**V1.0 明确不做（Out of Scope）** —— 任何一项被插入 V1，都需走变更流程

- ❌ 云端同步、多人协作、移动端/Web 版
- ❌ 角色库、人物关系图、灵感库、场景图库（→ V2.0~V2.2）
- ❌ AI 情节分析、AI 人物提取（→ V3.0），但 **接口抽象层在 V1 预留（附录 A）**
- ❌ EPUB / DOCX 排版导出（→ V3.1；V1 仅 TXT / Markdown）
- ❌ 账号体系、付费、插件市场
- ❌ macOS / Linux 打包（→ V1.1 评估）
- ❌ 图片 OCR、公式编辑、复杂表格排版
- ❌ 实时协作编辑、评论批注

### 1.6 术语表

| 术语 | 定义 |
|---|---|
| **项目 / 作品** | 一部小说，Inkwell 中的最高层级容器 |
| **卷** | 项目下的分卷（如"第一卷·少年篇"），用于组织章节，可选 |
| **默认卷** | 系统为每个项目自动创建的隐藏卷（BR-6），用于承载"不分卷"的章节，并作为删除非空卷与恢复孤儿章节的落点 |
| **章节** | 正文的最小组织单元，隶属于某个卷 |
| **设定文档** | 与正文并列的项目级参考资料（世界观、时间线、势力、名词表），不参与字数统计 |
| **章节版本** | 章节正文在某时刻的快照，写作中自动生成或用户手动创建。记作"章节版本 #N"，**不**与软件版本号（V1.0）混用。**版本号单调递增，回滚也产生新版本号**（BR-9） |
| **快照** | 生成一次章节版本的动作 |
| **暂存保存（pending）** | 自动保存连续失败或遭遇版本冲突时，把未保存内容暂存在本地（localStorage + `drafts/`）的机制，服务恢复后自动补写 |
| **字数** | 按 §2.3.1 规则统计的中文字数，**不含** HTML 标签，默认含标点 |
| **软删除** | 记录标记为已删除并移入回收站，数据仍在库中，可恢复 |
| **数据目录** | 运行时存放数据库、封面、媒体、备份的根目录，默认 `%USERPROFILE%/Documents/Inkwell` |

## 二、需求分析

### 2.1 用户故事与场景

| ID | 用户故事 | 场景说明 |
|---|---|---|
| US-1 | 作为网文作者，我希望双击一个 exe 就能开始写，不用装环境、不用开浏览器 | 首次使用，零配置启动 |
| US-2 | 作为作者，我希望能同时管理 3 本书，每本有自己的封面、简介和进度 | 项目列表页多项目切换 |
| US-3 | 作为作者，我希望能按"卷-章"组织大纲，并拖拽调整章节顺序 | 大纲结构调整 |
| US-4 | 作为作者，我希望写作时看到本章字数和全书总字数，知道今天写了多少 | 写作页状态栏 |
| US-5 | 作为作者，我担心电脑死机丢稿，希望自动保存且能找回一小时前的版本 | 自动保存 + 版本历史 |
| US-6 | 作为严肃文学作者，我希望能单独维护世界观、时间线，写作时随时查阅但不混进正文 | 设定文档 |
| US-7 | 作为作者，我希望定期把整本书导出成一个文件留底，或整盘备份 | 备份与导出 |
| US-8 | 作为作者，我希望搜索"某个地名"能同时找到章节正文和设定文档里的条目 | 全文搜索 |
| US-9 | 作为作者，我误删了一章，希望能从回收站找回 | 软删除恢复 |
| US-10 | 作为作者，我希望界面是浅色、安静的，不要有干扰写作的花哨元素 | 视觉与交互规范 |
| US-11 | 作为作者，我把旧稿（TXT，可能是 GBK 编码）导入时，希望不会变成乱码 | 导入编码探测 |

### 2.2 功能需求（V1.0）

优先级采用 MoSCoW：**Must** = 不做则 V1 不成立；**Should** = 强烈期望，资源紧张时可降级；**Could** = 有余力再做。

#### FR-1 项目基础信息管理（Must）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-1.1 | 创建 / 编辑 / 删除小说项目 | Must |
| FR-1.2 | 项目属性：书名、简介、封面图、分类标签、状态（连载/暂停/完结）、目标字数 | Must |
| FR-1.3 | 项目列表页：卡片式展示封面缩略图 + 书名 + 简介 + 总字数 + 进度（进度 = 总字数 / 目标字数；未设目标字数则不显示进度条） | Must |
| FR-1.4 | 项目设置页：修改基础信息、更换封面、删除项目 | Must |
| FR-1.5 | 记住每个项目"最后打开的章节"，重开时自动定位 | Should |
| FR-1.6 | 删除进入回收站，可恢复或彻底删除 | Must |
| FR-1.7 | 项目名允许重复，不加唯一约束（作品重名常见，以创建时间与 ID 区分） | Must |
| FR-1.8 | 封面文件缺失时显示默认封面图标，不报错、不阻断 | Should |

#### FR-2 卷-章大纲管理（Must）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-2.1 | 卷-章两级结构，支持卷的增删改与重命名；**删除非空卷时强制二选一确认："章节移动到默认卷"或"整卷连同章节一并删除（进回收站）"** | Must |
| FR-2.2 | 章节列表按序排列，支持新建、重命名、删除、拖拽排序；章节标题允许重复 | Must |
| FR-2.3 | 章节属性：标题、状态（草稿/初稿/定稿）、梗概、目标字数 | Should |
| FR-2.4 | 章节跨卷拖动；**合并卷 = 将卷 A 全部章节移入卷 B 末尾并删除卷 A**（操作前确认） | Could（V1.1） |
| FR-2.5 | 大纲树支持折叠/展开、键盘上下移动 | Should |

#### FR-3 富文本章节写作（Must）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-3.1 | 富文本编辑：加粗、斜体、标题、有序/无序列表、引用、分割线、撤销重做 | Must |
| FR-3.2 | 图片插入（本地图片存入 `media/`，相对路径引用，经 `/files/` 端点访问） | Must |
| FR-3.3 | 实时字数统计：本章字数 + 本卷字数 + 全书总字数 | Must |
| FR-3.4 | 中文排版适配：首行缩进 2 字符、合理行高与行宽 | Must |
| FR-3.5 | 自动保存（防抖 + 最大间隔，见 §2.3.2；连续失败或版本冲突时走暂存兜底） | Must |
| FR-3.6 | Markdown 快捷输入（输入 `# ` 转标题等），取决于编辑器能力 | Could（V1.1） |
| FR-3.7 | 专注/打字机模式（当前行居中、隐藏侧栏） | Should（V1.1） |
| FR-3.8 | 深色模式 | Could（V1.1） |
| FR-3.9 | 单章超过设计容量（>5 万字）时提示建议拆分，**不阻断写作**；>10 万字时强化提示（NFR-P2 仅在 ≤5 万字范围内承诺） | Should |
| FR-3.10 | 正文中图片文件缺失时显示"图片缺失"占位符，不报错、不崩溃 | Should |

#### FR-4 设定文档（Must）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-4.1 | 项目级设定文档区，与章节并列，不参与全书字数 | Must |
| FR-4.2 | 文档类型：世界观设定、时间线、势力地图、专有名词表、其他 | Must |
| FR-4.3 | 使用与章节相同的富文本编辑器 | Must |
| FR-4.4 | 每项目可建多篇，支持排序与分类筛选 | Should |
| FR-4.5 | 设定文档也具备版本历史（与章节对等；表结构 V1 建好，功能 V1.1 落地） | Should |

#### FR-5 自动保存与版本历史（Must）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-5.1 | 自动保存：输入停止 3s 触发，或距上次保存满 30s 强制触发 | Must |

### 2.3 关键业务规则

#### 2.3.1 字数统计规则（BR-1）

1. **统计对象**：去除 HTML 标签后的纯文本（`Chapter.content_text` 列，保存时一并计算并缓存）。
2. **CJK 字符**（中日韩统一表意文字、假名、谚文）：逐字计 1。
3. **西文**：按"单词"计，连续字母/数字串计 1。
4. **标点、emoji 与其他符号**：默认**计入**（符合网文平台惯例）；设置项可切换为"不计标点"，emoji 与符号随标点口径一并开关。
5. **不统计**：HTML 标签、图片、代码块（若有）、设定文档正文、卷名与章节标题。
6. **一致性**：章节字数变化时，异步重算所属卷与项目总字数缓存；设置页提供"重算全书字数"修复工具。

> 规则 4 需在设置中暴露开关，因为不同平台（起点/晋江/番茄）的统计口径不同，作者常需对齐。

#### 2.3.2 自动保存触发与失败兜底规则（BR-2）

```
输入停止 3s  → 保存正文（写 Chapter，不生成快照）
距上次保存 ≥30s 且有内容变更 → 强制保存一次
保存成功后 → 按 §5.3 分级策略判断"本次是否值得生成快照"
```

- 保存为**异步、非阻塞**；保存失败时状态栏变红并重试 3 次（退避 1s/3s/9s）。
- **连续 3 次重试仍失败 → 本地暂存兜底**：未保存内容同时写入前端 localStorage 与 `drafts/chapter_{id}_pending.txt`；状态栏持续红色告警，提供"导出当前章节到文件"逃生口；服务恢复后自动补写并清理暂存。
- **版本冲突（3002）→ 先落暂存再提示**：前端收到 3002 时，先把当前编辑器内容写入暂存，再提示用户刷新；刷新后自动检测暂存并询问"是否恢复未保存内容"。
- 应用关闭、切换章节、窗口失焦时立即强制保存；处于暂存兜底态时，关闭前弹出未保存提醒。

#### 2.3.3 排序规则（BR-3）

- `order_index` 采用**间隔步长 1000** 的整型排序。
- 取值算法：头部插入 = 当前最小值 − 1000；尾部插入 = 当前最大值 + 1000；中间插入 = floor((前一项 + 后一项) / 2)。
- 当相邻差值 ≤ 1 时，对该父节点下的记录做一次局部重整。

#### 2.3.4 删除与恢复规则（BR-4）

- 所有删除均为**软删除**：置 `is_deleted=1`、`deleted_at=now`，进入回收站。
- 删除项目 → 级联软删除其下的卷、章节、章节版本、设定文档。
- 删除非空卷 → 按 FR-2.1 二选一确认后执行。**默认卷不可删除**（BR-6）。
- 回收站保留 **30 天**，超过后由后台清理任务物理删除（BR-8 约束）。
- **恢复时校验父链**：父节点仍在回收站 → 提示"连同父级一并恢复"；父节点已被物理删除 → 章节挂到所属项目的默认卷，卷/设定文档挂到项目根级。
- 外键均声明 `ON DELETE CASCADE`，连接建立时执行 `PRAGMA foreign_keys=ON`。

#### 2.3.5 文件路径规则（BR-5）

- 数据库内一律存**相对于数据目录的相对路径**。
- 封面与正文图片写入时校验（格式白名单 jpg/png/webp，单张 ≤10MB，超尺寸自动压缩）。
- 删除章节时，其 `media/` 子目录延后到回收站清理阶段才物理删除。
- 图片与封面一律经 `GET /files/{relpath}` 访问（采用签名 token，ADR-009）。

#### 2.3.6 默认卷规则（BR-6）

| 规则 | 说明 |
|---|---|
| 创建时机 | 新建项目时自动创建一条 `is_default=1` 的卷；导入旧稿时同样先建默认卷再挂章节 |
| 可见性 | 大纲树中默认隐藏；**当项目不存在任何非默认卷时才显示**（否则用户看到空大纲会困惑） |
| 可操作性 | 不可删除、不可重命名、不参与卷排序（`order_index` 固定为 0） |
| 语义 | 承载"不分卷"的章节；同时是删除非空卷（FR-2.1 mode=move）与恢复孤儿章节（BR-4）的落点 |
| 统计 | 与其他卷一样参与卷内字数统计 |

#### 2.3.7 原子写入规则（BR-7）

- 备份文件（`.db`）与导出文件（`.txt` / `.md`）一律先写同目录下的 `*.tmp`，完成后用 `os.replace()` 原子替换。
- 启动扫描与备份列表枚举时忽略 `*.tmp` 文件，避免把半截文件当可用备份。
- 数据库迁移同理：迁移前备份走原子写入，保证 `prerestore` 备份本身完整。

#### 2.3.8 时间基准规则（BR-8）

- 持久化时间统一存 UTC；"每日 / 每周 / 30 天"这类按日期判定的策略，用**本地日期**并把"上次处理日期"写入 `app_meta`。
- 启动时若检测到当前时间**早于**上次记录的时间（系统时间回拨、跨时区、夏令时切换），则跳过本次自动清理与每日备份，记录 WARNING 日志并提示用户检查系统时间。
- 该规则覆盖：每日备份（FR-6.1）、回收站 30 天清理（BR-4）、快照保留清理（§5.3）、每周完整性检查（NFR-R3）。

#### 2.3.9 版本编号规则（BR-9）

- `chapter.version_no` 与 `chapter_version.version_no` **单调递增、永不回退**。
- 回滚不恢复到旧版本号，而是基于旧版本内容生成**新版本**（`change_type='restore'`），UI 展示为"由 #13 回滚至 #7，生成 #14"。
- 乐观锁 `expect_version` 以 `chapter.version_no` 为准。

## 三、竞品分析与技术选型

### 3.1 竞品差异化对比

| 产品 | 本地优先 | 卷章领域模型 | 版本历史 | 中文长篇适配 | 费用 | Inkwell 的相对优势 |
|---|---|---|---|---|---|---|
| Word / WPS | ✅ | ❌ | 弱（靠另存为） | 一般 | 付费/免费 | 领域模型 + 版本历史 |
| 网文平台后台 | ❌（数据在云端） | ✅ | 部分 | ✅ | 免费 | 数据主权 + 离线可用 |
| Notion | ❌ | ❌（靠模板） | 有 | 一般 | 订阅 | 零配置 + 离线 + 领域模型 |
| Obsidian | ✅ | ❌（靠插件） | 需插件 | 一般 | 付费商用 | 开箱即用，免配置 |
| Scrivener | ✅ | ✅ | 有 | 弱（汉化与中文本地化不足） | 付费 | 免费开源 + 中文语境 |
| **Inkwell（目标态）** | **✅** | **✅** | **✅** | **✅** | **免费开源** | — |

**结论**：Inkwell 不追求"功能最多"，而是追求"中文长篇小说场景下的最小完整闭环 + 数据主权 + 零配置"。

### 3.2 技术方案对比

| 对比项 | PyQt / PySide | 本地 Web（用户开浏览器） | **pywebview（选定）** | Electron |
|---|---|---|---|---|
| 独立 exe 运行 | ✅ | ❌ 需用户手动开浏览器 | ✅ | ✅ |
| UI 美观度上限 | 中 | 高 | 高 | 高 |
| 前端技术栈自由度 | 低 | 高 | 高 | 高 |
| 打包体积（经验预估·阶段四实测校准） | 40~70MB | 20~40MB | **35~60MB** | 100~200MB |
| 冷启动（经验预估） | 1~2s | 1~2s | **2~3s**（需拉起本地服务） | 2~4s |
| 常驻内存（经验预估） | 150~250MB | 120~200MB | **180~300MB** | 250~400MB |
| 工程化 / 可维护性 | 中 | 高 | **高** | 高 |
| 团队学习成本（人日，Python 背景） | 5~8 | 1~2 | **2~3** | 4~6 |
| 适合开源长期迭代 | 中 | 高 | **高** | 中 |

> 表中数值为**经验预估**，非实测。阶段四须实测并回填真实数据（D-06）。

**核心结论**：pywebview 把"网页的 UI 表达力"和"桌面软件的独立体验"结合起来。代价是需要额外拉起一个本地服务（约 +1s 启动、+60MB 内存），换来前后端解耦、便于调试、接口可被后续插件/脚本复用。

### 3.4 架构决策记录（ADR）

| ID | 决策 | 备选方案 | 理由 | 主要代价 |
|---|---|---|---|---|
| ADR-001 | 桌面壳用 pywebview（WebView2） | PyQt、Electron、Tauri | UI 表达力 + 独立 exe + 零学习成本 | 依赖 WebView2 Runtime |
| ADR-002 | 前后端通过本地 HTTP（FastAPI）通信 | pywebview `js_api` 直调 | 契约清晰、可独立调试、便于插件复用 | 需处理端口与安全暴露面 |
| ADR-003 | SQLite 单文件 + WAL | Markdown 目录、TinyDB | 事务、FTS5、单文件易备份 | 需自行处理并发与备份 |
| ADR-004 | 富文本用 Quill 2.x（零构建） | TipTap、TinyMCE | 与"无构建链"一致 | 高级排版弱于 ProseMirror |
| ADR-005 | 正文 HTML 存储 + `content_text` 冗余列 | Markdown、JSON(Delta) | 回显直接；纯文本供统计与 FTS5 | 双列同步维护，存储 +40% |
| ADR-006 | 分级快照策略（§5.3） | 每次保存都快照 | 避免版本表爆炸 | 自动快照粒度较粗 |
| ADR-007 | PyInstaller **onedir** 打包 | onefile | onefile 启动解压拖慢冷启动 | 分发为文件夹+exe |
| ADR-008 | FTS5 **external content** 模式 | FTS5 默认内容表 | 默认模式会复制一份正文，存储翻倍 | 需触发器同步；损坏需重建 |
| ADR-009 | **静态资源用短期签名 query token** 鉴权 | ① 沿用 `X-Inkwell-Token` 头（不可行：`<img>` 请求不带自定义头）；② 前端 fetch → blob URL（可行但内存与复杂度高） | `<img src>` 只能携带 URL 参数，签名 token 是唯一能在保持鉴权的同时让浏览器原生加载图片的方案；签名与会话绑定、短期有效，且仍受 Host 校验与路径白名单约束 | 签名会出现在 URL（本地日志不记录完整 URL，NFR-M4）；需实现签发与校验逻辑 |

### 4.5 启动与生命周期

```
1. 单实例锁 → 已运行则聚焦已有窗口并退出
2. 解析数据目录 → 不存在则初始化
3. 检测 WebView2 Runtime → 缺失则引导下载（NFR-C2）
4. 打开数据库 → PRAGMA foreign_keys=ON / journal_mode=WAL / busy_timeout=5000
5. 快速自检 PRAGMA quick_check（毫秒级）
   ├─ 异常 → 阻断启动，引导从 backups/ 恢复
   └─ 正常，但距上次完整检查 ≥7 天 → 后台执行 integrity_check（NFR-R3）
6. 待执行迁移 → 先原子备份当前库（NFR-R5 + BR-7），事务内按序应用，失败回滚
7. 【前台完成】渲染窗口与编辑器，拉取 /api/meta，恢复上次项目与章节 → 计入冷启动时间
─────────────── 以下全部后台异步，不阻塞可交互（NFR-R8） ───────────────
8. 时间基准检查（BR-8）：时间回拨则跳过本次清理与备份，记录 WARNING 并提示
9. 每日首次启动：创建数据库备份（原子写入）
10. 清理：过期备份、回收站（>30 天）、孤儿媒体文件；结果以通知呈现
11. 磁盘余量检查 → 低于阈值预警（NFR-R9）
12. 后台任务：WAL checkpoint（TRUNCATE）、FTS 索引去抖更新、字数增量重算
13. 退出：强制保存（含暂存检查与未保存提醒）→ 关闭服务 → 释放锁
```

### 4.6 备份恢复的运行时流程（FR-6.3）

```
1. 校验目标备份：复制目标 .db 到临时文件 → 打开并执行 PRAGMA quick_check
   → 读取 app_meta.schema_version 判断是否兼容（NFR-R7）
   ├─ 不通过 → 拒绝恢复，给出具体原因（文件损坏 / 版本不兼容），结束
   └─ 通过 → 继续
2. 锁定自动保存与全部写入，编辑器置只读遮罩
3. 关闭数据库连接（WAL checkpoint）
4. 原子备份当前库为 backups/inkwell_prerestore_YYYYMMDD_HHMM.db（BR-7）
5. 用目标备份替换 inkwell.db（原子替换）
6. 重新初始化连接 → 走 §4.5 第 4~6 步
7. 成功 → 解除只读，通知前端全量刷新
   失败 → 回滚到第 4 步的 prerestore 备份，提示用户
```

### 5.3 版本快照策略（分级）

| 类型 | 触发条件 | 保留规则 |
|---|---|---|
| **auto** | 距上次快照 ≥5 分钟 **且** 字数变化 ≥200 字 | 保留最近 30 条；每日首条额外保留 30 天 |
| **manual** | Ctrl+S / "存档" | 永久保留 |
| **milestone** | 章节标记"定稿"、卷/书完结 | 永久保留 |
| **restore** | 回滚前自动为当前内容建快照 | 永久保留 |

- **快照失败为非致命错误**：正文保存是主路径，快照失败仅记录日志 + 一次轻提示，延迟到下次触发条件再试。
- **时间基准**：每日首条判定依赖 `last_snapshot_daily_date`，时间回拨时跳过清理（BR-8）。
- **效果测算**：连续写作 1 小时 → 约 12 条 auto 快照，保留 30 条可回溯约 2.5 小时；配合每日首条可回溯一个月进度。

> 需在阶段二实装后用 AC-5 实测校准。

### 5.4 数据库运维

| 项 | 做法 |
|---|---|
| 并发 | WAL + `busy_timeout=5000`；写操作串行化到单一 writer 队列 |
| WAL 维护 | 后台定期 `wal_checkpoint(TRUNCATE)`（**假设：每 5 分钟或 WAL ≥32MB 时**）；备份前强制 checkpoint |
| 完整性 | 启动 quick_check；完整 integrity_check 每周一次或异常时；后台执行 |
| 索引维护 | FTS 索引由后台队列去抖更新（**假设：变更后 10s 批量合并**）；损坏时用"重建全文索引"修复 |
| 备份 | `sqlite3.Connection.backup()` 在线热备 + 原子写入（BR-7） |
| 迁移 | 迁移前原子备份（NFR-R5）；按 `schema_version` 递增顺序应用，**不支持降级**（NFR-M5）；每脚本附旧库 fixture 测试 |
| 清理 | 后台：过期备份、回收站 >30 天、孤儿媒体；时间回拨时跳过（BR-8） |
| 修复工具 | "重建全文索引""重算全书字数"，幂等 |

### 5.5 预留扩展表（V2.0+）

`character`、`character_relation`（V2.0）→ `inspiration`（V2.1）→ `scene_image`（V2.2）

**扩展点清单**：① `api/` 新增文件 → `server.py` 目录扫描自动注册；② `services/` 新增服务不改既有；③ `sidebar.js` 注册表 push 一项；④ `migrate.py` 追加迁移（迁移前自动备份）。

## 六、接口设计

### 6.1 接口约定

| 项 | 约定 |
|---|---|
| 基址 | `http://127.0.0.1:<随机端口>/api` |
| 业务接口鉴权 | 头 `X-Inkwell-Token`（NFR-S2）；token 经 pywebview 窗口对象注入，**不出现在 URL** |
| **静态资源鉴权** | `GET /files/{relpath}?sig=<签名>`，短期签名 token（ADR-009，NFR-S8）；仍受 Host 校验与路径白名单约束 |
| Host 校验 | 仅接受 `127.0.0.1` / `localhost`（NFR-S5） |
| 请求超时 | 前端默认 10s；导出/备份/恢复类长任务放宽至 120s（**假设值**），超时须给用户明确提示而非静默挂起（NFR-M4） |
| 统一响应 | `{ "code": 0, "message": "ok", "data": {...} }` |
| 字段级错误 | `data.errors: [{"field": "title", "reason": "不能为空"}]` |
| 分页 | `?page=1&page_size=50` |
| 时间格式 | ISO 8601（UTC，带 `Z`） |
| 大列表接口 | 章节树/章节列表仅返回元数据，不含正文 |
| 日志 | 请求日志只记方法、路径（**不含 query 中的签名**）、耗时、状态码（NFR-M4） |

**错误码**

| code | 含义 | 处理建议 |
|---|---|---|
| 0 | 成功 | — |
| 1001 | 参数校验失败 | 按 `data.errors` 逐字段提示 |
| 1002 | token 无效 | 重新注入 token |
| 2001 | 资源不存在 | 提示并刷新列表 |
| 2002 | 资源已删除 | 引导至回收站 |
| 3001 | 数据库错误 | 记录日志，提示重试 |
| 3002 | 版本冲突 | **前端先落暂存**（BR-2）再提示刷新 |

### 6.3 关键接口说明

**PUT `/api/chapters/{cid}/content`（自动保存）**

请求：`{ "content_html": "...", "client_saved_at": "...", "expect_version": 12 }`
响应：`{ "code":0, "data": { "word_count":3287, "project_word_count":128456, "saved_at":"...", "snapshot_created":true, "snapshot_version_no":13 } }`

- `expect_version` 乐观锁：不匹配返回 **3002**；**前端必须先落暂存再提示刷新**（BR-2、NFR-R6）。
- `snapshot_created` 由服务端按 §5.3 判定，前端不决定。
- `project_word_count` 为异步增量值，**最终一致**（秒级延迟）；状态栏以本地实时累加值为准。

**POST `/api/chapters/{cid}/versions/{vid}/restore`（回滚）**

服务端行为（事务内）：把当前正文存为 `change_type='restore'` 的永久快照 → 用目标版本内容覆盖 `chapter.content`（重新消毒并重算 `content_text`/`word_count`）→ **`version_no` 继续递增**（BR-9，绝不回退）→ 返回新版本信息。UI 展示为"由 #13 回滚至 #7，生成 #14"。

**GET `/api/files/{relpath}?sig=`**

- 校验顺序：Host → 签名有效性/有效期 → 路径规范化后必须落在 `covers/` 或 `media/` 内 → 文件存在性。
- 失败分别返回 4004（签名）、4003（路径）、404（文件缺失，前端降级为占位符/默认封面，FR-1.8/FR-3.10）。

## 附录 A：AI 接口抽象层

> V1 仅定义接口与注册机制，**不实现任何 Provider**；V3.0 按 D-08 执行（用户自带 Key、显式开启、外发前确认）。

### A.1 接口定义（backend/services/ai_provider.py）

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass

@dataclass
class PlotAnalysis:
    summary: str
    conflicts: list[str]
    pacing_notes: list[str]

@dataclass
class CharacterMention:
    name: str
    aliases: list[str]
    first_position: int

class AIProvider(ABC):
    """AI 能力抽象层：所有 Provider 实现同一契约，运行时可切换。"""

    @abstractmethod
    async def analyze_plot(self, chapter_content: str) -> PlotAnalysis:
        """分析章节情节。入参为去标签纯文本（content_text）。"""

    @abstractmethod
    async def extract_characters(self, chapter_content: str) -> list[CharacterMention]:
        """提取出场人物，供关联角色库（V2.0 character 表）。"""

    @abstractmethod
    def name(self) -> str:
        """Provider 标识，用于设置页展示与切换。"""
```

### A.2 Provider 规划与切换

| Provider | 时点 | 说明 |
|---|---|---|
| `NullProvider`（默认） | V1 | 返回"AI 功能未启用"；全程不联网 |
| `CloudAPIProvider` | V3.0 | DeepSeek / OpenAI 等，用户自带 Key；发送前弹确认并明示数据范围（NFR-S4） |
| `LocalModelProvider` | V3.0 | 本地 Ollama 等，数据不出本机 |

- 注册表 `PROVIDERS: dict[str, type[AIProvider]]`，选择结果持久化到 `app_meta.ai_provider`。
- 外发约束：正文**仅在用户显式触发单次分析时**外发当章 `content_text`；不发快照、不发设定文档、不批量外发。
