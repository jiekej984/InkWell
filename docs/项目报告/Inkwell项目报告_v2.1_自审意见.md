## 二、B 类：会导致实现 bug 的设计漏洞（8 项）

| # | 问题 | 后果 | 处置 |
|---|---|---|---|
| B1 | 关系唯一索引没含 `custom_label`，且 `custom_label` 可为 NULL | 「其他/青梅竹马」与「其他/指腹为婚」被误拦；SQLite 中 NULL 不参与唯一比较，又拦不住完全重复 | `custom_label NOT NULL DEFAULT ''`，唯一索引改为 `(from, to, type, custom_label)` |
| B2 | 组织软删只标记父级 | 子组织「父已删、自己还活跃」→ 图上孤儿节点 | 软删**同事务递归**标记全部子组织与成员；恢复递归还原 |
| B3 | 删根组织时仍提供「上移一级」 | 没有父级可挂，逻辑分叉 | 根组织时该选项置灰，只能取消或一并删除 |
| B4 | 只规定了软删，没规定查询过滤 | 「已删角色还挂在组织里」「已删组织还出现在卡片上」 | 明确所有查询 join 主体过滤 `is_deleted=0` |
| B5 | 主组织被删后的着色未定义 | 节点颜色不确定 | 降级为「无主组织」，取第一个成员组织色；无组织则灰；不自动改选 |
| B6 | 组织未设 `faction_id` 时归哪个立场未定义 | 阵营模式分组错乱 | 向上继承最近祖先组织的立场；全链都没有则归「未分组」 |
| B7 | 同一角色在同一组织可能有多段身份（弟子→长老），但唯一索引拦死 | 无法晋升建档 | 明确只保留一条活跃身份、职位直接改；历史留 V2.1 时间轴 |
| B8 | 师傅关系中断后又恢复（第 1~40 章、第 60~80 章）被唯一索引拦 | 无法表达 | 用不同 `custom_label` 区分（如「师徒·重逢后」），见 B1 的索引变更 |

## 三、C 类：实现缺口（不补会各自发挥，8 项）

| # | 问题 | 处置 |
|---|---|---|
| C1 | `#64` 只写「返回 nodes + edges + groups」，没定义字段 | 补完整 JSON 契约：`kind` / `active` / `truncated` / `groups` 语义 |
| C2 | P10 组织 Tab 和 P11 组织模式都画组织树，职责重叠 | 明确：**P10 管理（增删改）、P11 只读查看（点击跳回编辑）**，同源不存两套 |
| C3 | 双击组织展开成员无上限 | 一次最多 20 个，超出显示「还有 N 人」 |
| C4 | 角色字段用纯文本还是富文本没定 | 一律纯文本、`textContent` 渲染，不走 Quill、不用 `innerHTML`（顺带消掉 XSS） |
| C5 | 布局保存无体积上限，且可能覆盖其它模式的坐标 | payload ≤1 MB；JSON 内按三模式分命名空间，只覆盖当前模式 |
| C6 | 组织关联的设定文档被删后怎么显示没定 | 显示「原文档已删除」，允许重新关联；软删文档标灰但不清关联 |
| C7 | 出场检索依赖 505 万字 fixture，仓库未必保留 | 任务 5.10 补一句：若不存在先写生成脚本；该需求标 P2 可延 |
| C8 | 死亡角色怎么画、从写作页进画布要不要带当前章，都没定 | 死亡角色加虚线圈；从写作页进入时默认带 `chapter_id`，顶部显示「按第 X 章显示 ✕」可取消 |

## 四、D 类：明确接受、不改的取舍（3 项）

| # | 取舍 | 理由 |
|---|---|---|
| D1 | 角色/组织不并入全局 FTS | 角色页自带搜索 + 出场反查已覆盖；字段语义复杂，FTS 收益低 |
| D2 | 成员职位历史不保留 | 保留历史需要时间轴与区间重叠校验，成本高；V2.1 做时间轴时再补 |
| D3 | 组织徽记不做 | 需要新增列与图片链路，价值低；立绘已覆盖「图」的需求 |
