## 一、项目概述

### 1.1 项目名称
**Inkwell**（墨水瓶）— 一款本地部署的小说写作辅助工具

### 1.2 项目定位
为小说作者提供一个**本地运行、数据自主、功能可扩展**的桌面写作环境。
核心目标是把"写小说"这件事从零散的文档、备忘录、脑子里的灵感，整合到一个统一的工作台里。

### 1.3 设计原则
- **本地优先**：所有数据存在用户自己电脑上，不上云、不联网也能写
- **体验优先**：双击exe就能用，不折腾环境、不打开浏览器
- **可扩展**：第一版先把项目管理核心打扎实，后续模块（角色库、灵感库、AI分析等）像插件一样往里加
- **开源友好**：代码结构清晰，适合放GitHub持续迭代

## 二、需求分析

### 2.1 第一版（V1.0）必须实现的核心功能

#### 模块一：项目基础信息管理
- 创建 / 编辑 / 删除小说项目
- 每个项目包含：书名、简介、封面图、分类标签、创建时间
- 项目列表页：多项目切换，展示封面缩略图
- 项目设置页：修改基础信息、更换封面、删除项目

#### 模块二：大纲与章节写作
- **卷-章两级结构**：一部小说可以分卷（如"第一卷·少年篇"），卷下挂章节
- 章节列表：按顺序排列，支持拖拽排序、重命名、新建、删除
- **富文本编辑器**：章节正文写作区，支持加粗、斜体、标题、列表、引用、图片插入等
- 写作辅助：实时字数统计、当前章节进度、全书总字数

#### 模块三：世界观 / 设定文档
- 项目级别的设定文档区（和章节并列，不混在正文里）
- 文档类型：世界观设定、时间线、势力地图、专有名词表等
- 同样用富文本编辑器编写
- 每个项目可以建多篇设定文档

#### 模块四：自动保存与版本历史
- **自动保存**：写作过程中定时（如每30秒）自动保存，不丢稿
- **版本历史**：每次保存生成一个版本快照，记录时间和字数
- 版本回滚：可以查看历史版本内容，一键恢复到某个版本
- 版本列表：按时间倒序展示，显示各版本的字数差异

## 三、技术选型

### 3.1 整体方案
**pywebview + FastAPI + 前端原生HTML/CSS/JS**

```
┌─────────────────────────────────┐
│         用户双击 Inkwell.exe     │
│  ┌─────────────────────────────┐ │
│  │   pywebview 桌面窗口壳       │ │
│  │  ┌───────────────────────┐ │ │
│  │  │   前端页面 (HTML/CSS/JS)│ │ │
│  │  │   简约浅色写作工具风格   │ │ │
│  │  └───────────────────────┘ │ │
│  │           ↕ HTTP API         │ │
│  │  ┌───────────────────────┐ │ │
│  │  │   FastAPI 后端服务      │ │ │
│  │  │   数据存储 / 文件管理   │ │ │
│  │  └───────────────────────┘ │ │
│  └─────────────────────────────┘ │
│         数据存在 Documents/Inkwell/ │
└─────────────────────────────────┘
```

### 3.2 为什么选这个方案

| 对比项 | PyQt原生桌面 | 本地Web(浏览器打开) | **我们选的 pywebview** | Electron |
|---|---|---|---|---|
| 独立exe运行 | ✅ | ❌要开浏览器 | ✅ | ✅ |
| UI美观度 | 一般 | 高 | **高** | 高 |
| 打包体积 | 中 | 小 | **中** | 大(100MB+) |
| 工程化/可维护 | 一般 | 好 | **好** | 好 |
| 前端技术栈自由度 | 低 | 高 | **高** | 高 |
| 适合开源长期迭代 | 中 | 高 | **高** | 中 |

**核心结论**：pywebview 把"网页的好看UI"和"桌面软件的独立体验"结合起来了，既不像PyQt那样UI写起来费劲，也不像浏览器方案那样需要用户手动开浏览器，打包出来就是一个exe。

### 3.3 技术栈明细

| 层级 | 技术 | 用途 |
|---|---|---|
| 桌面壳 | pywebview | 原生窗口，加载前端页面 |
| 后端框架 | FastAPI | REST API，处理数据和业务逻辑 |
| 数据库 | SQLite (SQLAlchemy) | 结构化数据存储 |
| 富文本编辑器 | 开源富文本库（如Quill/TipTap） | 章节和设定文档编辑 |
| 前端样式 | 原生CSS（或轻量框架） | 简约浅色写作工具风格 |
| 打包工具 | PyInstaller | 打包成Windows exe |
| AI接口 | 抽象层设计 | 后续支持云端API + 本地模型双切换 |

### 4.2 数据存储位置

**运行时**：所有数据存在用户的 `Documents/Inkwell/` 目录下
```
Documents/Inkwell/
├── inkwell.db              # SQLite数据库（项目、章节、版本等结构化数据）
├── covers/                 # 项目封面图
│   ├── project_1.jpg
│   └── ...
└── media/                  # 正文中插入的图片
    ├── chapter_1/
    └── ...
```

这样设计的好处：
- 符合Windows桌面软件的习惯
- 用户可以直接备份整个Documents/Inkwell文件夹
- 卸载软件不会丢数据

## 六、UI设计方向

### 6.1 整体风格
**简约浅色 / 写作工具风**
- 参考：Notion、Obsidian、Typora 的浅色模式
- 主色调：米白/浅灰背景 + 深灰文字，少量品牌色点缀
- 字体：中文用思源黑体/苹方，英文用Inter
- 重点是**专注写作**，界面元素尽量克制

## 八、预留的扩展接口设计

### 8.1 AI接口抽象层（backend/services/ai_provider.py）
设计一个统一的AI Provider接口，后续可以无缝切换：
```python
class AIProvider(ABC):
    @abstractmethod
    async def analyze_plot(self, chapter_content: str) -> str:
        """分析章节情节"""
    
    @abstractmethod
    async def extract_characters(self, chapter_content: str) -> list:
        """提取出场人物"""

# 后续实现：
# - CloudAPIProvider（调用DeepSeek/OpenAI等云端API）
# - LocalModelProvider（调用本地Ollama等）
```
用户可以在设置里选择用哪个，现在先把接口留好。

### 8.2 模块化设计
后续加新功能时，遵循：
- 新模块 = backend/api/xxx.py + backend/services/xxx.py + frontend/js/xxx.js
- 不改动现有模块的核心逻辑
- 侧边栏导航动态注册，加新模块自动出现在导航里
